# 内置路由策略与聚合模型

## 当前方案

- `/routing` 只读展示后端代码内置策略，不需要创建策略、流程或槽位。
- `/models/aggregated` 中直接选择一个策略和候选接入模型；策略本身不区分模型类型，聚合模型负责约束候选模型类型。
- 策略统一定义在 `backend/app/modules/routing/strategies.py`，通过 `GET /api/admin/v1/routing/strategies` 获取。聚合模型保存 `default_routing_strategy`、按顺序排列的 `routing_model_ids` 以及可选的 `fallback_model_id`。

| 策略编码 | 候选模型 | 选择行为 |
| --- | --- | --- |
| `single` | 恰好 1 个 | 固定选择；模型停用则无可用结果 |
| `round_robin` | 2 至 30 个 | 跳过停用模型，在剩余候选间按配置顺序轮询 |
| `least_latency` | 2 至 30 个 | 跳过停用或无延迟指标的模型，选择最低延迟；相同延迟时按模型 ID 选择 |

保存时校验候选存在、不重复且都与聚合模型类型相同。兜底模型可从当前聚合的候选模型（界面标注“聚合节点”）或模型管理中所有同类型的接入模型选择；两种来源最终都保存为接入模型 ID，不引入聚合模型之间的嵌套引用。兜底模型可以留空，但填写时必须存在且与聚合模型类型一致。启用时至少需要一个已启用的候选模型或兜底模型。策略没有选中可用模型时，管理端模拟会尝试兜底；上游请求失败后的切换仍待网关转发阶段实现。停用操作需要确认。管理端的 `POST /api/admin/v1/aggregate-models/{id}/simulate` 支持传入 `round_robin_index` 与 `latencies={模型ID: 毫秒数}` 来预览选择结果。

聚合编码与对外模型名称均可使用大小写英文字母、数字、下划线、连字符、小数点及中文字符（CJK 基本区和扩展 A 区），不允许空格或其他符号；各字段最多 128 个字符。唯一性仍按保存的原始值精确匹配，大小写有区别。

**目前只是配置和模拟：** `/v1` 仍未使用这些策略进行真实转发；尚无跨实例轮询计数器，也没有从实际请求采集的实时延迟指标。运行时应以聚合模型 ID 为键原子递增轮询计数，在转发后采集接入模型维度的延迟，并定义指标过期与无指标时的回退规则。不能将管理端“已启用配置”视为已对客户端开放端点。

## 旧配置处理

先前的流程表和历史聚合数据继续保留，不自动删除。旧版 `workflow` 配置仍可通过已有 `GET /routing/workflows`、`GET /routing/workflows/{id}` 和 `POST /routing/workflows/{id}/simulate` 读取或模拟；创建、修改流程的接口已关闭。聚合模型列表将不属于内置策略的记录标记为“旧配置”。管理员可编辑此类聚合模型，明确选择内置策略及候选模型后保存，新配置不再引用旧流程，旧流程记录本身仍保留供后续清理或审计。原演示数据中的 `priority`/`weight` 也属于待转换旧配置。
