## 约定与范围

- 目标范围：按 `docs/requirements-aligned-design.md` 等设计文档逐步实现全部功能，包含前后端和自定义管理台风格。
- 开发协作：助手负责代码实现和代码层面的检查；页面展示及交互效果由用户校验。
- 前端使用 Vue 3、Vite 和 pnpm；后端使用 FastAPI、SQLAlchemy 和 uv。
- 本地开发需通过 Vite 代理将 `/api` 和 `/v1` 请求转发至后端（默认 8001），API 使用相对路径。
- 管理台后续新增弹窗统一使用居中的 `.app-modal-overlay` 和 `.app-modal-panel`；弹窗宽度按内容设置，长内容在弹窗内滚动，确认操作也使用页面内居中弹窗，不使用浏览器原生 `window.confirm`。
- 管理台下拉框统一使用 `frontend/src/AppSelect.vue`，传入 `options` 与 `v-model`；输入框和展开选项均采用 `frontend/src/styles/index.css` 中的 `.app-select` 主题样式，不再直接使用原生 `<select>`。
- 用户组独立于组织，创建时不选择组织，也不通过用户组赋予组织角色。现阶段仅平台管理员可修改用户组和成员；旧关联数据由 `20260926_0004` 迁移备份到 `user_group_legacy_scope`，更新数据库需执行迁移。
- 项目可不选择组织，此时为平台级项目，仅平台管理员可创建；平台级项目由负责人及项目成员控制访问，不继承组织权限。已有关联组织的项目保留原规则。数据库需执行 `20260926_0005` 迁移；平台级项目的 Key、网关日志与用量支持可空组织 ID。
- 后续成功、失败和一般提示统一调用 `frontend/src/utils/toast.ts` 的 `showToast("success" | "error" | "info", 文案)`；由应用级 `ToastHost.vue` 在视口顶部居中显示 3 秒，不再在页面或弹窗中重复渲染消息块。

## 当前已完成

- 凭证中心管理员视角：个人 Key、项目 Key 已提供列表、创建、编辑、轮换、启停及管理员重复查看接口与管理页面。支持绑定聚合模型或直连接入模型，配置 TPM、QPS、按 UTC 自然周/月计算的 Token 额度、排队/阻塞模式及最大等待时间。创建或轮换时可选填 2-20 位自定义 Key 前缀，留空使用 `agw_`；修改已有 Key 的前缀必须轮换。随机密钥的 SHA-256 哈希用于网关鉴权；新建或轮换 Key 另以 `AI_GATEWAY_PROVIDER_ENCRYPTION_KEY` 加密存储，管理员可通过眼睛入口再次查看并生成基于当前站点地址与授权模型的 Linux/Windows curl 示例。迁移 `20260927_0015` 增加可空密文列，`20260927_0016` 保存可空自定义前缀；仅存哈希的历史 Key 无法恢复，需手动轮换，不自动使其失效。加密密钥必须稳定且妥善保存，明文不出现在常规列表和详情。面向普通用户的客户端权限与自助管理留待后续。
- 网关一期运行时：`/v1/models` 按 Key 授权返回模型；`/v1/chat/completions` 支持 LLM/VLM、OpenAI/Claude/Gemini 文本聊天及统一 SSE（OpenAI 兼容协议支持多模态），`/v1/embeddings`、`/v1/rerank`、`/v1/ocr`、`/v1/images/generations` 支持供应商 OpenAI 兼容路径的非流式转发。各接口复用 Key 及模型授权、Redis QPS/TPM 和 UTC 周/月额度、排队位置与阻塞等待。按上游 Token usage 结算；Rerank/OCR/图像生成缺少 usage 时以及聊天流未返回最终 usage 或中断时保守按预留量计入，并记录请求日志。部署须提供可靠 Redis 和供应商解密密钥。仅完成 Key 级治理，项目级配额、跨实例聚合调度、供应商故障切换、ASR/TTS 和更多协议能力尚未接入，不能将此阶段视作完整生产网关。
- 项目骨架：FastAPI 应用、管理及网关路由骨架、初始数据库模型和迁移、Vue 控制台布局与 API 基础目录。
- 开发联调配置：工作区已有前端代理配置、环境示例文件和本地服务相关调整；这些改动尚未提交。
- 管理台导航：`frontend/src/router/navigation.ts` 定义 10 个业务分组；侧栏支持分组展开、当前路由高亮和窄屏抽屉。未实现的入口标注“规划中”并指向占位页。
- 登录页：已改为深色品牌区与浅色表单区的响应式布局；保留登录调用和跳转，支持密码显示切换，移除了预填凭据。
- 账户区域：用户名称和角色显示在侧栏底部；静态“工作空间”区块已移除。点击账户卡片会弹出操作菜单，退出登录收在菜单内，支持点击外部或按 Esc 收起。
- 模型治理第一阶段：供应商列表接入真实数据库，支持搜索、分页、详情、创建、编辑、启停及读取已存储健康状态；页面提供居中表单与启停确认弹窗。写操作仅平台管理员可用，供应商 API Key 使用独立 `AI_GATEWAY_PROVIDER_ENCRYPTION_KEY` 加密存储，不回传明文。设置 API Key 前须配置并妥善保存该密钥；健康状态目前不是实时探活。
- 模型治理入口顺序调整为：供应商管理、模型管理、路由策略、聚合模型、在线调试。供应商连接配置支持多协议地址、多上游 Key 和密钥轮换；模型管理关联所属供应商的协议与可选 Key。数据库迁移 `20260926_0007` 会将旧单协议和旧 Key 转入独立记录。
- 独立节点管理入口和管理 API 已撤下，旧节点表及历史数据保留，避免破坏原有引用。模型创建/编辑直接配置可选的模型 Base URL、供应商 Key、地域、最大并发、最大 Token 容量（`context_window`）及超时；“接入模型编码”在界面标注为“平台内部模型编码”。模型 Base URL 留空时存储为 `NULL`，读取生效地址时动态继承供应商的 Base URL；已有模型的显式地址保留，不会自动改为继承。迁移 `20260926_0008` 会从关联协议回填旧模型的地址。目前支持网关部分协议转发，尚无上游实时探活或模型级并发执行。
- 后续治理目标：模型通过聚合模型及路由策略统一对外；客户端 Key 只授权聚合模型。本阶段尚未实现聚合发布及客户端 Key 限制，不能将当前管理页或网关骨架视为真实路由能力。
- 路由策略已收敛为代码内置的只读列表：单模型、轮询分流、最低延迟。聚合模型直接选择策略及同类型候选模型，不再要求创建流程或槽位。旧流程只保留读取及模拟接口，写入口已关闭；旧聚合配置可显式转换为新策略。`20260927_0011` 增加直接候选模型字段，历史迁移不删除。聚合模型现可通过已授权 Key 接入 `/v1`，但轮询序号仅为进程内计数，最低延迟尚无实时测量，发布权限与健康调度未实现；详见 `docs/routing-workflow-design.md`。
- 聚合模型新增可选的兜底接入模型：可从当前聚合候选（界面称“聚合节点”）或模型管理中的同类型模型选择；策略无可用结果时管理端模拟会尝试兜底，真实网关失败切换仍待实现。聚合编码和对外模型名称支持大小写字母、数字、下划线、连字符、小数点及中文，不允许空格或其他符号；迁移 `20260927_0012` 新增可空外键字段，需备份后执行 `uv run alembic upgrade head`。
